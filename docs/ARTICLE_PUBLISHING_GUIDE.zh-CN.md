# Maddy 文章发布指南

## 最短流程

1. 打开 GitHub 仓库的 `src/content/articles/`。
2. 点击 **Add file → Create new file**。
3. 文件名使用简短英文，例如 `compactness-intuition.md`。
4. 复制 README 中的模板，填写标题、摘要、分类和正文。
5. 提交到 `main`。Actions 检查通过后，网站会自动更新。

## 元数据

- `title`：准确说明文章解决的问题。
- `description`：一到两句话，避免只重复标题。
- `kind`：`concept` 概念、`proof` 证明、`problem` 例题、`note` 札记。
- `topics`：主领域，例如分析、代数、几何、概率、组合。
- `series`：可选的连续专题名称。
- `level`：入门、进阶、专题。
- `prerequisites`：建议先掌握的概念；没有时写 `[]`。
- `featured: true`：将文章放到首页主推荐位，同一时期建议只保留一篇。
- `draft: true`：不生成公开页面。

## 数学公式

行内公式使用单个美元符号：`$e^{i\pi}+1=0$`。

独立公式使用双美元符号：

```text
$$
\int_a^b f(x)\,dx=F(b)-F(a).
$$
```

构建会自动用 KaTeX 排版。复杂公式提交前应运行 `npm run build`，确保没有语法错误。

## 推荐文章结构

1. 先写出真正的问题，而不是先抄定义。
2. 给出一个最小例子或反例。
3. 再引入严格定义与符号。
4. 证明中明确指出关键转折。
5. 最后记录适用边界、失败路径或后续问题。

## 固定写作规约：Stop Slop

每篇文章发布前都要完成这一遍检查。AI 起草、人工起草、翻译和旧文修改一视同仁。仓库根目录的 `AGENTS.md` 也保存了同一要求，后续自动化写作工具进入仓库时应先读取并遵循。

### 先改结构

- 第一段直接给出问题、反例、具体计算或主张。不要用“本文将探讨”“让我们深入了解”宣布文章开始。
- 一节只承担一个推理任务。小标题要指向数学内容，不用“深入分析”“核心洞察”“总结与展望”这类通用标题。
- 结尾只有在增加边界条件、失败路径或新问题时才保留。不要换一种说法重复摘要。

### 再改句子

- 删除“值得注意的是”“显而易见”“不难发现”“至关重要”“意义重大”。若事实并不明显，就补推导；若确实明显，直接写事实。
- 少用“不是 X，而是 Y”“不仅 X，而且 Y”的现成骨架。只有在纠正一个真实的数学误解时保留对比，并紧接定义、例子或后果。
- 不让抽象词代替动作。写“连续性只控制函数值的极限”，不要写“连续性揭示了更深层的本质”。
- 避免连续三个长度和句式相近的句子，避免每段都以一句漂亮口号收尾。
- 不用破折号制造停顿。改成句号、逗号，或重写句子关系。
- 保留假设、量词、适用范围和不确定性。去除 AI 腔不能以牺牲数学准确性为代价。

### 发布前人工复核

逐项回答：

1. 开头是否在三句话内进入具体数学问题？
2. 每个抽象判断后是否有定义、式子、例子或机制？
3. 是否有可以删除而不损失信息的预告、强调或总结？
4. 证明是否写出了真正困难的转折，而不是用“容易得到”越过？
5. 句子节奏是否自然，是否出现整齐但空泛的排比？
6. 文章是否保留了作者实际的困惑、选择或判断？

最后运行 `npm run check:prose`。它会拦截一部分明显套话和破折号，但无法判断文章是否具体、诚实或有数学内容；人工复核不能省略。

## 图片与文件

把图片放进 `public/images/`，在文章中使用 `/Maddy/images/文件名.png`。文件名使用英文小写与连字符，不要包含空格。

## 发布失败

打开仓库的 **Actions** 页面，进入最新一次 `Deploy Maddy to GitHub Pages`。常见原因是元数据漏项、日期格式错误或公式语法错误。修正后再次提交即可。
